# 主动回收（Recycle）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 max-run 到点前自动 `suspend → resume`，验收业务恢复，避免免费计划冷却递增。

**Architecture:** 新增 `lib/recycle.js`（纯计划函数 + 可注入状态机），由 OpenChamber 内 keepalive 与 `scripts/recycle.js --once` 两个入口共用；`store.js` 存配置/运行态，`store-lock.js` 提供带心跳的跨进程锁；控制动作直连，验收走代理。

**Tech Stack:** Node 24 CommonJS、`node:test`、`node:sqlite`（既有）、Windows 计划任务。

**Spec:** `docs/superpowers/specs/2026-11-13-recycle-design.md`

## Global Constraints

- CommonJS、零原生依赖、`node --test`、`scripts/sync.mjs`。
- 平台字段/域名不得进入 6 个通用模块（`store-lock/proxy-fetch/sub2port/ratelimit/scheduler/inventory-probe`）。
- 控制动作（suspend/resume/snapshot）直连；业务请求与验收走账号代理，失败可降级直连但必须记录。
- 所有阈值来自 `settings.recycle`，不硬编码机器名、账号、maxRun。
- 未配置 `verifyCommand` 的机器绝不暂停。
- 仓库公开：文档/测试不得写入 API Key、节点 URI、账号邮箱。

## Review Focus

1. `runStartedAt` 缺失/非法/未来时间：跳过并在状态里写明原因，绝不暂停。
2. `maxRunMinutes` 在计划与执行之间变化：suspend 前必须重读。
3. 平台先进入 max-run 冷却：suspend 后出现未来 `cooldownUntil` 时不得 resume。
4. resume 成功但应用未就绪：exec 就绪重试 + verify 超时，失败走 bootstrap，二次失败标 degraded。
5. 进程中途退出：下轮 RECONCILE 必须把 `suspended/resuming` 的机器 resume 并验收。
6. 两个入口同时到点：跨进程锁 + `lastRunStartedAt` 去重。

function harness(machineStates, results = {}) {
  const calls = [];
  let index = 0;
  const direct = {
    async listMachines() {
      calls.push('list');
      return [machineStates[Math.min(index++, machineStates.length - 1)]];
    },
    async power(id, action) { calls.push(action); if (results.powerError) throw new Error(results.powerError); },
    async snapshot() { calls.push('snapshot'); },
  };
  const proxy = {
    async exec(id, cmd) {
      calls.push(`exec:${cmd}`);
      return results.exec ? results.exec(cmd, calls) : { exitCode: 0, stdout: 'ok', stderr: '' };
    },
  };
  return { calls, direct, proxy };
}

test('suspend then resume then verify resets the run', async () => {
